# 人话翻译固定映射表

> **用途**：L0 卡片 / L1 五块渲染层把审计层的技术表述翻译为人话。**命中即用，未命中不翻译，禁止 LLM 自由生成翻译。**
>
> 规则：
> 1. 渲染时按"技术表述"列匹配，命中后用"人话"列替换。
> 2. 多条命中时取最具体的那条（如"规则1触发 score<0.5"优先于"黄区"）。
> 3. 未命中的技术表述保留原文，不得改写、不得自由翻译、不得解释。
> 4. 本表只用于人读层（L0/L1）；机读层（L2/L3/JSON）保留技术表述原文。

---

## 一、证据等级与总分

| 技术表述 | 人话 |
| :--- | :--- |
| 证据等级 green（≥8.0） | 证据够了，可以拍板 |
| 证据等级 yellow（4.0~7.99） | 有些证据，但还不够拍板 |
| 证据等级 red（<4.0 但 ≥0.5 已通过闸口） | 证据薄弱，仅供参考 |
| 总分 X，黄区（4.0~7.99，X 为任意具体分数） | 有些证据，但还不够拍板 |
| green ≥8.0 | 证据够了，可以拍板 |
| 核心 evidence threshold capped to yellow（总分≥8.0 但无单条 base_weight≥2.5） | 总分够高，但没有一条"硬证据"撑腰，只能算中等 |
| 核心证据门槛未达（insufficient，无单条硬证据） | 缺少一条"硬证据"撑腰，证据不足、无法给出方向性结论 |

## 二、闸口规则

| 技术表述 | 人话 |
| :--- | :--- |
| 规则1触发（score<0.5） | 几乎没找到相关论文，需要你决定下一步 |
| 规则2触发（有效论文为0） | 没找到能用的论文，以下全是推断 |
| 规则3触发（\|估算÷基准\|>1.5 或 <0.67） | 估算值和基准差太远，没法判断 |
| score<0.5 活检查点 A/B/C | 需要你决策：扩大检索 / 你提供论文 / 我用训练数据推断 |
| 证据极度匮乏（score=0.3） | 几乎没找到相关论文，需要你决定下一步 |
| 证据极度匮乏（valid=0） | 没找到能用的论文，以下全是推断 |
| 证据极度匮乏（valid=0），需你决策 | 没找到能用的论文，需要你决策：扩大检索 / 你提供论文 / 低置信度推断 |
| 🔴 模拟数据 | 这是模拟数据，不是真实文献 |
| 🔴 模拟数据 — 以下结论基于训练数据推断 | 这是模拟数据，以下结论基于训练数据推断，不得立项 |
| 全文降级【确证】→【推断】 | 没有直接证据，所有判断降为推断 |

## 三、证据类型与权重

| 技术表述 | 人话 |
| :--- | :--- |
| RCT（权重 5.0） | 随机对照试验，证据很强 |
| FDA/NMPA 批准（权重 5.0） | 监管机构已批准，证据很强 |
| Meta-analysis（权重 2.5） | 多项研究的汇总分析 |
| Industry_standard（权重 3.0） | 行业标准 |
| Patent（权重 3.0） | 专利文献 |
| Prototype_implementation（权重 1.5） | 有原型实现，但未规模化 |
| Simulation（权重 0.5） | 仅有仿真数据 |
| Expert_opinion（权重 0.5） | 专家观点，无直接数据 |
| is_mock=true（模拟数据） | 这是模拟数据，不是真实文献 |

## 维护规则

- 新增领域术语时，必须在"技术表述"列给出完整原文，"人话"列给出 ≤20 字的口语化替换。
- 禁止用"可能是"、"大概"等模糊措辞；人话必须确定。
- 同一技术表述只能有一条人话映射；如有歧义，拆分为多条带上下文的映射。
- 本表版本随 SKILL.md 版本同步更新。
